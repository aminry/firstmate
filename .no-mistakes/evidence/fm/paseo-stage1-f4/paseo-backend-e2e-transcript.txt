===============================================================
C. The misroute this ordering prevents: a tmux pane inside a Paseo host
===============================================================
Paseo leaks PASEO_AGENT_ID straight through a tmux spawn, so a tmux pane opened by a
Paseo-hosted firstmate carries BOTH markers. $TMUX names the layer actually executing,
so paseo is checked LAST and the tmux task is NOT rerouted (no notice, no refusal - the
run gets past the backend boundary and stops later, here on a deliberately bad project path).

$ TMUX=/tmp/tmux-501/default,12345,0 PASEO_AGENT_ID=agt_9f2c4d1e bin/fm-spawn.sh demo-task <bad-path> ...
bin/fm-spawn.sh: line 2246: cd: /tmp/paseo-evidence.kKykHm/spawn-both/no-such-project: No such file or directory
exit status: 1  <- backend resolved to tmux; no paseo notice and no paseo refusal
